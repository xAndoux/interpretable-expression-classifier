# Interpretable facial-expression classifier — MATLAB reconstruction

> **Reconstruction, not recovered work.** This is a new, independently authored implementation based only on a high-level description of Andrew Awe's earlier academic project (Rice, 2024): seven classes, bottom-up spatial features, and geometric/intensity variation. No original source, model, results, or training data were recovered. This implementation does **not** reproduce, verify, or claim the historically mentioned ~81% figure. It implies no Rice University or other institutional affiliation or endorsement.

This repository is a transparent, dependency-light baseline for classifying **visible facial-expression categories in a labeled dataset**. Expressions are not a direct reading of a person's inner emotional state, intentions, or identity. Do not use this code for consequential decisions about people.

## What is included

- Seven canonical classes: `angry`, `disgust`, `fear`, `happy`, `sad`, `surprise`, `neutral`.
- Grayscale conversion and a built-in bilinear resize to 64×64; median/IQR contrast normalization and clipping.
- Coarse spatial 6×6 block mean, standard deviation, horizontal/vertical gradient, gradient magnitude, and reflection-error features, plus row/column profiles (264 features).
- Deterministic train/validation/test partitioning and explicit duplicate rejection.
- Z-score statistics learned from training rows only, with safe handling of constant features.
- Nearest-centroid and one-vs-rest ridge candidates using ordinary MATLAB matrix algebra.
- Candidate selection by **validation macro F1 only**, followed by held-out test evaluation.
- Confusion matrices and per-class precision, recall, F1, support, accuracy, and macro F1 in a report generated by code.
- A portable regression suite, an Octave CI workflow, and a synthetic **abstract-pattern** execution smoke test.

No licensed face dataset, face detector, alignment model, trained weights, screenshots, claimed benchmark, or original project artifact is bundled.

## Requirements

The implementation targets MATLAB R2020b or newer and recent GNU Octave. Core training and feature extraction use base matrix/vector operations. Image file input uses the platform's `imread`, `imfinfo`, and `imwrite` support; supported formats can vary by installation. No Statistics, Deep Learning, or Computer Vision Toolbox is called. MATLAB itself has **not** been used to verify this project; the accompanying test record should be consulted for the actual Octave version/results.

## Quick start

From this directory in MATLAB:

```matlab
run_tests
run_smoke
```

Or from a shell with Octave installed:

```bash
octave --no-gui --quiet --eval "run_tests"
octave --no-gui --quiet --eval "run_smoke"
```

The smoke command generates `results/synthetic-report.md` and `results/synthetic-results.mat`. **The images are generated geometric patterns, not faces.** Any measured values only demonstrate deterministic execution on separable synthetic patterns; they are not facial-expression accuracy, a benchmark, or evidence of useful real-world performance. Generated outputs are gitignored.

## Real-data experiment

### 1. Obtain data responsibly and prepare crops

Supply a dataset that you have permission to use and whose license permits your intended use and redistribution (if any). Read its terms yourself; no download is performed by this project. Known research sources to investigate include:

- [CK+ (Cohn-Kanade+) information at the University of Pittsburgh](https://www.pitt.edu/~emotion/ck-spread.htm)
- [JAFFE at zenodo](https://zenodo.org/records/3451524)
- [FER2013 Kaggle competition page](https://www.kaggle.com/c/challenges-in-representation-learning-facial-expression-recognition/data)
- [AffectNet](http://mohammadmahoor.com/affectnet/)

These are pointers, not assertions that all sources have identical seven labels, identical terms, public availability, or permission to repackage. CK+/JAFFE may not directly contain every category in sufficient quantity. FER2013 labels include the seven canonical names above; other datasets need documented label mapping or a different study design. Do not silently merge differently collected/labeled datasets and call the result a controlled benchmark.

Inputs must already be **aligned, cropped frontal-ish face images**. This baseline performs no detection, landmark localization, pose correction, identity inference, or annotation. A consistent crop/alignment protocol is essential: otherwise position, background, and head pose can become shortcuts. Keep the same preprocessing policy for every partition.

Directory layout (exact folder names):

```text
/path/to/dataset/
  angry/
    image_001.png
  disgust/
  fear/
  happy/
  sad/
  surprise/
  neutral/
```

Accepted filename extensions are `.png`, `.jpg`, `.jpeg`, `.bmp`, `.tif`, `.tiff`, `.pgm`. Other files or unexpected subdirectories are rejected instead of silently skipped. Floating-point arrays passed directly to `preprocess_image` must be in `[0,1]`; integer images are scaled according to their integer type.

### 2. Prefer identity-disjoint evaluation

Without metadata, splitting is deterministic and class-stratified **by image**, not by person. That can leak identity and acquisition conditions between partitions and inflate performance. It is not adequate evidence of generalization to new people.

Create an identity CSV outside the repository or under a gitignored data location:

```csv
relative_path,identity
angry/example_001.png,subject_001
happy/example_002.png,subject_001
neutral/example_003.png,subject_002
```

Paths use forward slashes and are relative to the dataset root. Identities can occur in multiple classes; all rows with the same identity remain in one partition. Paths/identities must be nonempty and contain no commas; quoted CSV syntax is intentionally not supported. See `identity_map.example.csv`.

The grouped splitter deterministically reserves identity groups so each class appears in train, validation, and test, then greedily balances group sizes. It requires sufficient independent groups for every class and fails rather than weakening disjointness. This is appropriate when one dataset has identities across expression classes. **If identity is correlated with class** (for example, single-expression subject groups), a grouped splitter may be impossible or change the problem substantially; disclose that rather than dropping the safeguard. For small datasets, consider separately implemented grouped cross-validation with an outer held-out test.

### 3. Run and interpret

```matlab
addpath('scripts')
results = run_dataset('/path/to/dataset', '/path/to/identity_map.csv');
```

Omit the second argument only when identity metadata truly is unavailable, and retain the report's warning:

```matlab
results = run_dataset('/path/to/dataset');
```

This creates `results/dataset-report.md` and `results/dataset-results.mat`. Model selection occurs on validation data. Do not repeatedly inspect test results and adjust preprocessing, features, lambdas, split seed, or data inclusion: doing so turns test data into tuning data. If changes are needed, document them and obtain a genuinely untouched evaluation set. The stored experiment contains paths and labels for auditability; protect any sensitive metadata accordingly.

## Method

### Preprocessing

1. Decode an aligned crop and convert RGB using fixed Rec. 601 luma weights.
2. Resize using bilinear interpolation at output pixel centers.
3. Subtract the image median and divide by its interquartile range. Near-constant IQR falls back to population standard deviation; unusable constant images are rejected.
4. Clip to ±5 robust scale units and scale to `[-1,1]`.

Per-image normalization can reduce illumination sensitivity, but it can also discard informative absolute intensity and amplify noise. It does not solve pose, occlusion, demographic bias, or label ambiguity.

### Spatial features

For each block in a 6×6 grid, extract mean, population standard deviation, centered horizontal/vertical gradient means, mean gradient magnitude, and mean absolute horizontal reflection error. Six values × 36 blocks = 216 features. Sixteen-row mean/std profiles and sixteen-column mean profiles add 48 features, for **264 total**.

These are hand-engineered local intensity/geometric proxy descriptors, not anatomical landmarks or semantic facial-action measurements. Reflection error is only a loose symmetry cue and is sensitive to imperfect alignment. Feature names are retained in `dataset.featureNames` for inspection. Standardized ridge coefficients and centroid differences can be examined, but high-dimensional correlated feature importance is not automatically causal or uniquely identifiable.

### Learning and evaluation

Training features determine the mean and population standard deviation for z-scoring. Constant training features receive scale 1; validation/test values are not used to fit statistics. Nearest centroid computes squared Euclidean distances to class means. Ridge solves

```text
W = (Z' Z + lambda I) \ (Z' Y)
```

with a final unpenalized intercept column. Candidate lambdas are `[0.01, 0.1, 1, 10, 100]`. Highest validation macro F1 wins; exact ties follow the fixed order centroid then increasing lambda. Training accuracy is diagnostic only. Test metrics are calculated after selection. Metrics are computed over all seven classes, including zero support/prediction classes as zero; on tiny datasets macro F1 can therefore look low even with good predictions in observed classes.

Exact duplicates are rejected **before splitting**, comparing normalized decoded pixel content. Fingerprints only locate candidates; exact matrix comparison decides duplicates. This is not cryptographic hashing and does not detect all near-duplicates, crops, augmentations, frames, or same-person images. Group-aware upstream deduplication remains necessary.

## Tests and CI

`scripts/run_portable_tests.m` (invoked by `run_tests.m`) exercises class ordering, resizing, preprocessing, spatial descriptors, deterministic image/identity splits, train-only normalization, metrics with known answers, centroid/ridge fitting, duplicate rejection, and end-to-end synthetic determinism. Temporary generated PNGs are test fixtures, not face data.

`.github/workflows/octave.yml` installs Octave on Ubuntu, runs the same tests, runs the synthetic smoke demo, and uploads the generated report. The workflow runs from the repository root. CI status must be checked on an actual pushed run; the file's existence is not evidence that GitHub Actions passed.

## Limitations

- There is no measured real-face performance here until a user supplies data and runs it.
- An image-level split can leak identity, scene, and augmentation information; use identity metadata and external person-disjoint evaluation.
- Labels may reflect posed appearance, annotator convention, or dataset construction rather than emotional truth.
- Dataset imbalance, selection bias, demographic bias, small samples, compression, and inconsistent crops can dominate results.
- Nearest centroid/ridge are intentionally simple baselines, not claims of state-of-the-art recognition or reproduction of another system.
- Generated reports are measurements of a particular run, not independent validation, clinical evidence, or deployment approval.
